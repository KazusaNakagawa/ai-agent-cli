ソースから使う・毎日の運用

リポジトリを clone すると、Web UI に加えて、毎朝の自動実行、週次リキャップ、ターミナルからの Q&A、ポートフォリオのスナップショットなどのコマンドが使えます。

セットアップ

必要なもの: Python 3.11〜3.13、uv、ログイン済みの Claude Code CLI。Discord や Notion に配信する場合は、Discord Bot と Notion インテグレーションも用意します。

git clone https://github.com/KazusaNakagawa/ai-agent-cli.git
cd ai-agent-cli
cp .env.example .env      # 必要に応じて DISCORD_TOKEN、NOTION_API_KEY などを書く

cd apps/python
uv venv .venv
uv pip sync requirements.txt

cd ../web && npm install  # Web UI を使う場合だけ

clone した環境では、設定ファイルは apps/python/config/briefing.json、生成物は apps/python/output/ に置かれます。認証情報はキーチェーンのサービス名 ai-agent に保存されます（npx 版の brief-lens とは別です）。

Web UI を起動する

bin/serve.sh               # API（:8000）と Web UI（:3000）を起動し、ブラウザを開く
bin/serve.sh --no-browser  # ブラウザを開かない

ポートは環境変数 API_PORT / WEB_PORT で変えられます。Ctrl + C で両方とも止まります。

日次の実行（workflow.sh）

定型の処理は bin/workflow.sh にまとまっています。

bin/workflow.sh                   # 登録されているワークフローの一覧
bin/workflow.sh run daily         # 日次の実行（下の表を参照）
bin/workflow.sh run briefing      # 日次ブリーフィングだけ
bin/workflow.sh run weekly        # 週次リキャップ（金曜以外はスキップ。--force で強制実行）
bin/workflow.sh run daily --dry-run   # 認証情報の確認だけ

run daily は、次の処理を順に行います。

  1. 日次ブリーフィングを生成して配信する
  2. 金曜日なら、週次リキャップを生成する
  3. bin/chat.sh の会話を output/chat_archive/ に保存する（Claude Code が古い会話記録を消す前に残すため）
  4. Claude Code の会話記録に、単価が登録されていないモデルがないかを確認する

そのほかのコマンド

コマンド用途
bin/chat.shブリーフィングに対してターミナルで質問する（bin/chat.sh 2026-05-16 で過去の日付、--list でセッション一覧）
bin/portfolio.shconfig/holdings.json から、構成比・為替エクスポージャー・配分ルールの検査を含むスナップショットを作る
bin/chart.sh price保有銘柄の株価を 100 起点に揃えた比較チャートを作る（--period 1y、--tickers で指定）
bin/money.sh銀行明細の CSV を取り込み、月次の収支をレポートする（import / report / review）
bin/archive.sh先月分のブリーフィングを zip にして rclone で Google Drive にアップロードする
bin/recover.shスリープの影響でセクター調査が欠けた日のブリーフィングを補う。当日分が完成していれば何もしない
bin/self_agent.sh判断ログからペルソナのプロファイルを作り、Notion に投稿する
bin/local_llm.shローカル LLM モード（Ollama + Chroma）

どれも apps/python/bin/ にある本体を呼び出す薄いラッパーです。全コマンドの一覧は README にあります。

毎朝自動で実行する

macOS では launchd、Linux などでは cron で、bin/workflow.sh run daily を毎朝決まった時刻に実行できます。設定手順はリポジトリの launchd-setup.md と cron-setup.md を参照してください。

スリープ中の Mac は、どのスケジューラでも動かせません。

無人で実行するには、実行時刻に Mac が起きている必要があります。つまり、蓋を開けたまま AC アダプタにつないでおく必要があります。蓋を閉じると、電源の種類に関係なくスリープします。

蓋を閉じたバッテリー駆動の Mac では、ジョブは数十秒しか続かない短い復帰（DarkWake）の中で起動します。Claude との通信が途中で切れ、再試行を繰り返すうちに、ブリーフィングを 1 つも作らないまま利用枠だけを消費します。caffeinate -ims でも防げません（-s は AC 電源のときだけ有効なため）。

この条件を満たせない場合は、朝に手動で bin/workflow.sh run daily を実行する運用をおすすめします。メンテナ自身も現在は手動で実行しています。

開発する

cd apps/python && .venv/bin/pytest -v   # Python のテスト
cd apps/web && npm test                 # Web UI のユニット・コンポーネントテスト
cd apps/web && npm run test:e2e         # Playwright の E2E テスト
cd packages/brief-lens && npm test      # npx ランチャーのテスト

テストは apps/python/tests/config/briefing.json を読むので、個人の設定がなくても実行できます。依存の更新方法やブランチの運用は、リポジトリの testing.md と CLAUDE.md にあります。
